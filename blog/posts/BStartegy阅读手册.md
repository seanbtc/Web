## 1. 全流程总览

一句话：**选得出来 → 审得过 → 落得下 → 跑得稳 → 看得住 → 退得出**。

```
┌───────────────────────────── 研究（离线，可重复） ─────────────────────────────┐
│  数据（全历史 K 线）                                                          │
│      │                                                                        │
│      ▼                                                                        │
│  选优 ──► 阶段 A（闸门+评分→短名单）──► 阶段 B（稳健性电池）──► 阶段 C（分级） │
│      │                                        │                               │
│      └── 种子精修 / 邻域扫描 ─────────────────┘                               │
│                                               ▼                               │
│                         尾门（样本外初筛）──► 决策包（DECISION）              │
└───────────────────────────────────────────────┬───────────────────────────────┘
                                                │ 人工评审（五件套 + 显著性 + 组合口径）
                                                ▼
                           定档（规模/杠杆）──► 转换（三段验证）──► 部署
                                                │
                                                ▼
┌────────────────────────────── 实盘（在线，7×24） ─────────────────────────────┐
│  4H 收线 ─► 指标计算 ─► 信号（震荡+趋势双确认）─► 仓位/风控 ─► 下单网关 ─► 交易所 │
│                                                                              │
│  监控：回放对账 · 六闸门 · 策略健康 · 持仓对账 · 全局急停 ─► 钉钉 / 面板      │
└───────────────────────────────────────────────┬───────────────────────────────┘
                                                │
                                                ▼
                         反馈：版本冻结 vs 实盘对账 ─► 执行统计反哺 ─► 下一轮选优
```

参数更新的标准流程是 **8 步**（⓪ 为可选的一条命令封装）：

| 步骤 | 内容 | 产物 |
|---|---|---|
| ⓪ | 单命令迭代（可选） | polish → neighbors → 尾门 → 决策包 |
| ① | 种子邻域精修 | 种子 ±2 步小空间选优 |
| ② | 邻域定向扫描 | 单维 ±1/±2 步变体 |
| ③ | 闸门 + 确认包 | 尾门初筛、五件套、显著性、决策包 |
| ④ | 组合口径回放（定档前必做） | 双腿合并净头寸 + 盯市回撤 |
| ⑤ | 用户定档 | 规模 / 杠杆档位 |
| ⑥ | live 转换 | 候选 → 实盘参数文件（三段验证） |
| ⑦ | both 状态对齐 | 起点与初始资金标定 |
| ⑧ | 部署 | 拉取 + 只重启受影响服务 + 冒烟 |

> 研究只走到决策包，**绝不自动改实盘**；上线永远是人工动作。

## 2. 口径先行：数据与窗口

流程里所有"好坏"都建立在同一套口径上，先统一语言：

### 2.1 数据

- **全历史以交易所官方接口（fapi）为准**，本地规范库存放（按标的/周期分目录，带 sha256 清单）；
- 月档归档数据仅作**交叉核对**（曾发现归档陈旧行，不作为主数据）；
- 每次数据补齐后刷新清单（sha256 / 行数 / 首末时间），保证报告可复现；
- 研究流程**不改写**实盘进程正在追加的 live 数据文件。

### 2.2 窗口

| 窗口 | 当前口径 | 用途 |
|---|---|---|
| 训练窗 | 2021-11-09 → 2026-06-19 | 选优打分、阶段 A |
| 验证窗 | 2026-06-20 → 数据末 | 选优打分、阶段 A |
| 全窗 | 2022-01-01 → 数据末 | 确认包分窗 |
| 主窗（滚动） | 2025-07-01 → 数据末−15 天 | 确认包 / 基准 |
| 样本外（OOS） | 训练起点前一年 | 尾门、确认包硬约束 |
| 多起点 A | 2019-11 起月度起点 → 数据末 | 尾门粗筛、确认包 |
| 多起点 B | 同上，固定 12 个月窗 | 确认包 |
| 锁箱 | 最近 N 个月全程禁入搜索，只揭盲一次 | walk-forward |

> 时间口径：内部统一 UTC 存储，展示用北京时间；K 线周期 4H。

## 3. 第一步：选优（参数研究）

选优解决的是"候选从哪里来"。有两条路径，互不冲突：

### 3.1 路径一：全空间深优（探索）

一条命令跑完整条流水线（预检 → 选优 → 阶段 A/B/C → 材料 → 校验 → 回执）：

```bash
python3 research/pipeline.py --symbol BTCUSDT --interval 4h
```

- **阶段 A（筛选）**：样本量 / 交易频率 / 风险 / 集中度 / t 值五类闸门 → 复合评分 → 去重 → 取前 3% 进入短名单；
- **阶段 B（稳健性电池）**：折外一致性 + 成本×1.5 压力 + 邻域 ±1 档探针；
- **阶段 C（分级）**：A/B/C 分级 + 报告 + 候选池。

### 3.2 路径二：种子精修（围绕现役改进）

现役参数就是起点，围绕它做小范围深挖（一条命令串联）：

```bash
python3 research/iterate.py --seed <现役参数文件> --direction long --name <批次名>
```

```
种子精修(polish) → 邻域扫描(neighbors) → 合并短名单 → 尾门 → 决策包(DECISION)
```

- **种子必被扫到（不变量）**：warm-start 搜索空间只对越界维度做最小放宽；台账第 1 条（BASE）必须与种子**逐键一致**，不一致直接判失败；
- 训练段被硬拒的 trial 会跳过验证窗（分数不可比）→ 短名单自动剔除这类行；
- 精修与全空间深优最终都汇入同一条评审链（尾门 → 决策包）。

### 3.3 搜索层门槛（先筛掉"看起来赚但不可用"的）

| 门槛 | 当前值 |
|---|---|
| 回撤硬顶 | **25%**（与阶段 A 对齐） |
| 浮亏硬顶 | 35% |
| 样本下限 / 年化频率 / 目标笔数 | 按周期处方注入（`profiles.json` 单一来源） |
| 计分 | 净利取 `log1p` **单调压缩**（保留"越高越好"，只压数量级，不设平坦截断区） |

### 3.4 选择质量（让"选出来的"更可能在实盘兑现）

| 机制 | 作用 |
|---|---|
| 折外聚合（`wf_eval`） | 固定参数 × 连续折外窗 → 正折比例 / 最差 / 中位 / 浮亏峰值；评「参数兑现力」 |
| 累计多重检验（`trial_registry`） | 跨批次累计试验数 N → DSR 用累计 N（比单轮更保守）；OOS 使用留痕 |
| walk-forward（周批） | 折内重拟合 + 折外拼接 + 参数漂移 + 锁箱一次性揭盲；评「优化流程本身」 |
| OOS 轮换 | 同一段样本外数据使用 ≥3 次应轮换 / 降级 |

## 4. 第二步：评审与定档（人工红线）

这一步的原则：**证据说话，绝不自动上线**。

### 4.1 确认包：五件套

| # | 检查 | 判据 |
|---|---|---|
| ① | 样本外（OOS） | OOS 净利 > 0 且浮亏在限内 |
| ② | 多起点 A / B | 多数起点为正、任意起点峰值浮亏 ≤ 50%、无长期不收敛起点 |
| ③ | 分窗评估 | 全窗 / 主窗 / OOS 逐项对照，不劣化 |
| ④ | 浮亏全清 | 多起点任一起点浮亏 ≤ 50% |
| ⑤ | 连亏压力 | 合成回撤分布 P95 ≤ 0.75 |

另附**实盘条件检查**：插针余量、清算缓冲、费用压力（fee×1.5）、kill 线。

### 4.2 显著性

- **DSR（Deflated Sharpe Ratio）**：多重检验校正后 ≥ 0.95 视为显著（用累计试验 N）；
- **BH-FDR**：候选池多重检验校正。

### 4.3 对照口径

- 与**现役基线**、**买入持有**同窗口、同规模逐项对照；
- "更优" = 风险不劣化的前提下，收益 / 尾部有改善；
- 决策包（`DECISION.md`）是**唯一人工评审入口**：候选按 confirm 后全窗原始净利排序，附显著性结论。

### 4.4 组合口径回放（定档前必做）

同一账户上两方向 = **净头寸合并运行**，单方向确认包覆盖不到组合的真实风险，所以必须做双腿合并回放（`both_sim`）。四种口径由浅到深：

| 口径 | 含义 |
|---|---|
| 已实现回撤 | 本金 + 已实现权益的峰谷 |
| 浮亏率 | 已实现 + 区间最差价浮动 |
| 收盘盯市（MTM close） | 逐根收盘的完整权益路径 |
| **盘中极值盯市（MTM intrabar）** | 含每根 bar 的有利/不利极值——**组合风险以此为准（最保守界）** |

判读要点：
1. 组合 MTM（intrabar）与单方向风险对照，并与 kill 线口径对齐；
2. 出现「单方向都赚、组合却亏」的年份要能解释（净头寸对齐/承接交易特性）；
3. 组合名义上限 = 两腿上限之和，保证金与波动一并核对。

### 4.5 定档

- 决策依据 = 单方向确认包 + 组合口径回放 + 对照表；明确记录用户口径（收益优先 / 稳健优先）；
- 阶梯工具逐档回放（0.5 → 2.5），**强制校验 `仓位 × 杠杆 ≤ 5`**。

## 5. 第三步：转换与上线

### 5.1 转换（候选 → 实盘参数文件）

- **只改候选源键**（公共段 + 本方向段）；基础设施与 live 特有键不动；
- 旧文件先备份；写盘原子替换；
- **三段验证**：
  - 1a 源键等价：新文件与候选逐键一致；
  - 1b 非源键零漂移：引擎加载→保存后无差异；
  - 2 真实回测一致：新旧参数各跑一遍，结果逐位一致；
- 验证失败**默认回滚**（保留失败现场）。

### 5.2 both 状态对齐（部署前）

- 先用一个**已知的线上结果**校准复现器（逐位一致）后才可信任其预测；
- 标定内容：`live_state_start`（起点）+ `initial_capital`（使回放净值 ≈ 账户实际资金）；
- 账户里手工/旧参数留下的持仓，bot **不会认领**——"对齐"指账户与 bot 状态一致，必要时先平掉遗留仓位；
- 数据补到**最新已收盘** K 线（第 7 列 = `(high+low)/2`，这里踩过坑）。

### 5.3 部署

1. 本地：语法 / 单测 / 冒烟 / 数据与参数文件核对；
2. 提交并推送（部署流程本身不提交代码）；
3. 服务器：工作区脏检查 → 拉取 → 只重启**受影响的服务**（参数变更 = 只重启策略进程）；
4. **部署后必须核对 bootstrap 日志**：
   - 回放区间是否符合 `live_state_start`；
   - 恢复后的状态（空仓/多/空）与净值是否符合预期（偏差 > ±3% 复查）；
   - 无 Traceback、进程存活、其它服务 PID 不变；
5. 下一根 4H 收线观察首轮信号；首单核对订单号与记录。

> 参数错了不可怕，可怕的是"不知道错了"——所以每一步都要有可对照的锚点。

## 6. 第四步：实盘运行

### 6.1 一根 4H K 线收线后发生什么

```
收线对齐（收到已收盘 K 线）
   └─► 指标计算（6 类：RSI / 随机 RSI / MFI + MACD / Supertrend / 均线交叉）
          └─► 日线裸 K 形态概率（10 种形态加权 → 方向概率）
                 └─► 信号判定（震荡类 ≥ 阈值 且 趋势类 ≥ 阈值 → 双重确认）
                        └─► 延迟过滤（信号需持续 N 根 K 线，防抖）
                               └─► 仓位计算（净值 × 杠杆 × 概率映射，按最小步长取整）
                                      └─► 双方向虚拟仓合并 → 目标净头寸
                                             └─► 风控（分级止盈 / 移动止损）
                                                    └─► Webhook → 下单网关
```

### 6.2 双方向（both）模式

- 多空各自维护**虚拟仓位**（独立参数、独立止盈止损），交易所只看到**净头寸**；
- 好处：两个方向可以独立优化；避免不必要的换向交易；
- 代价：组合风险 ≠ 单方向之和——这也是为什么定档前必须做组合口径回放。

### 6.3 风控（独立于收线）

- 4H 间隔里价格可能剧烈波动，**止盈止损由独立监控线程秒级轮询**，不等收线；
- 分级止盈：每触发一级平掉一部分，同时把止损向有利方向移动；
- 止损闭环：止损触发也走统一下单链路并留痕（不裸奔）。

### 6.4 下单链路

```
策略 ──► 下单网关（账号路由 / 双向持仓 / 幂等订单号 / 失败分类重试） ──► 交易所
```

- **幂等订单号**：开仓新意图新 id；平仓重试与重启恢复复用同一 id；重复命中不静默重试，转人工对账；
- 失败分类：可重试（网络/限频）与不可重试（参数/权限）分开处理；
- **全局急停开关**：文件级开关，即时生效、fail-closed；开仓与平仓两处门控，触发时不清 pending、解除后继续。

### 6.5 资金与仓位安全

- 分账运行：每个策略腿独立账本，固定净值口径；
- 杠杆档位有人工定档，`仓位 × 杠杆 ≤ 5` 是硬约束；
- 下单金额受单笔上限与可用资金约束（取数失败时宁可不交易）。

## 7. 第五步：监控与对账

实盘上线不是终点，而是"被监督"的起点。监控体系分四层：

### 7.1 轻量回放对账

用同一份数据与参数**回放实盘时段**，把回放订单与实盘订单逐笔比对：

- 漏单 / 多单 / 方向错 / 数量偏差；
- 延迟分布（信号 → 成交）与滑点分布；
- 边界情况（空窗期、强平、部分平仓）单独归类，不误报。

### 7.2 六类闸门

| 闸门 | 看什么 |
|---|---|
| 订单审计 | 回放 vs 实盘逐笔差异（g0 级） |
| 参数一致性 | 部署落锚（引擎版本 + 参数哈希 + 数据哈希）与现网对比，漂移即报警 |
| 开仓对齐 | 信号→成交的延迟/价格偏差分布，漏单/多单统计 |
| 分布健康 | 胜率 z 检验 / 盈亏因子 / 单腿收益中位 / 交易频率 / 持仓时长 / 连亏 |
| 组合净敞口 | 双腿合并的净敞口 / 总名义 / 净值比 |
| 持仓对账 | 交易所实际持仓 vs 机器人账本（容差 1%） |

> 闸门默认先 **observe（只记录）**，用实盘数据复核口径后再切 alert——避免上线初期误报刷屏。

### 7.3 策略健康与展示

- **参数一致性（M1）**：参数/引擎/数据哈希与部署锚点比对；
- **开仓对齐（M2）**：配对样本、延迟 p90、偏离 p95；
- **分布健康（M3）**：样本进度条 + 达标后的胜率/PF/连亏等；
- **维护建议（M4）**：异常时给出「查锚 / 核对执行 / 重维护」建议——**只建议，不自动执行**；
- **周报（M5）**：每周固定时间推送健康摘要；
- 面板：看板内「策略模块 / 策略健康」切换，独立页保留。

### 7.4 实际账务

- 每笔成交回查交易所逐笔记录（`userTrades`），回填**实际手续费 / 实际已实现盈亏**；
- 模型估算与实际值偏差超过阈值 → 告警；
- 汇总口径：实际优先、模型兜底，标注覆盖率。

### 7.5 告警原则

- **只推事实**：异常、新订单、周报；正常状态不打扰；
- 去抖与静默：重复告警合并，未开仓的空窗期不刷"警告"；
- 告警内容人话化（"引擎版本变化：A → B"，而不是堆原始字段）。

## 8. 第六步：反馈与迭代

### 8.1 部署即冻结预测

上线前把候选的预测（全窗/OOS/多起点/浮亏/组合口径 + 参数哈希）**冻结存档**；观察期结束后拿实盘结果对账——偏差是"参数失效"还是"执行损耗"，一目了然。

### 8.2 执行统计反哺

- 回放对账沉淀的**延迟 / 滑点分布**，反过来标定回测的执行模型（成本假设）；
- 让下一轮选优更接近真实成交环境，而不是纸面最优。

### 8.3 失效信号与处置

| 信号 | 处置 |
|---|---|
| 参数漂移 / 数据哈希变化 | 查锚、重落锚、必要时重维护 |
| 分布显著偏离（胜率、频率、连亏） | 降档观察 / 暂停该腿 |
| 执行长期未对齐（漏单/滑点超标） | 先修执行链路，再谈参数 |
| 多起点/组合风险超过约束 | 立即降档或停用（果断放手） |

### 8.4 定期重估

- 每周 walk-forward 周批自动跑（折内重拟合 + 折外拼接），结果进决策包；
- 样本外数据使用次数留痕，达到上限即轮换；
- 重估 ≠ 自动上线：任何参数变更仍然走 ④→⑧ 的完整评审链。

## 9. 角色分工与红线清单

### 9.1 分工

| 角色 | 职责 |
|---|---|
| 研究 | 选优、阶段 A/B/C、确认包、决策包（只产出证据） |
| 人工评审 | 看证据做决定：通过 / 打回 / 观察（唯一决策点） |
| 定档 | 选择规模与杠杆档位（记录口径） |
| 转换 | 候选 → live 参数文件 + 三段验证 |
| 部署 | 服务器拉取、只重启受影响服务、部署后核验 |
| 运行 | 策略进程 7×24，收线处理、下单、风控 |
| 监控 | 回放对账、闸门、健康视图、对账与告警 |
| 展示 | 面板与公开页面（只读） |

### 9.2 红线清单（每次执行必查）

1. 参数文件放在项目路径下（引擎推断依赖路径）；
2. 种子评估与台账 BASE 逐位一致；
3. 复现器先对一个已知线上结果逐位校准；
4. 转换三段验证全 PASS；
5. 数据补到最新已收盘（第 7 列 = `(high+low)/2`）；
6. **组合口径回放必做**，风险以盘中极值 MTM 为准；
7. 部署前置 = 已提交推送 + 服务器工作区干净；
8. 部署后核对 bootstrap 日志（区间 / 状态 / 净值）；
9. **研究不自动改实盘；上线是人工动作**。

## 10. 结语：三个原则

- **充分的验证**：单测 + 真实冒烟 + 多起点 + 对账 + 观察期，证据必须能复现；
- **理性的判断**：结论由分布和证据说话，口径单源，防过拟合，安全排序（资金安全 > 稳定 > 收益 > 增长）；
- **果断的决策**：异常即阻断（急停/熔断即时生效），成立即推进，不利即放手（失效就停，不恋战）。

> 系统能长期活着，靠的不是某一次选出的"神参数"，而是这条从**选优 → 评审 → 上线 → 运行 → 监控 → 反馈**的闭环本身。
